# 一个 CRUD 的全栈链路：契约是怎么断的

> **一句话结论：** 全栈联调九成的返工，都出在「字段名、类型、空值、分页格式」这四件事上。

## 现象

一个再普通不过的列表页，前后端联调花的时间是写页面本身的两倍。

症状：

- 前端拿不到数据
- 编辑回显失败
- 新增保存报错
- 分页越界
- 时间展示错乱

## 链路拆解

```
浏览器 → 请求参数 → 路由 → 参数校验 → 业务逻辑 → DAO → 数据库
                                    ↑
                              错误最容易藏在这一段
```

| 层 | 必须对齐什么 | 错了会怎样 |
|---|---|---|
| 前端请求 | 参数名、类型 | 传参后后端接不到、类型报错 |
| 接口层 | 校验规则、默认值 | 漏传参数直接 500、默认值理解不一致 |
| 业务层 | 空值语义、权限 | `null` 和空字符串混用，判断逻辑走偏 |
| DAO 层 | 字段映射、排序 | 驼峰/下划线映射失败、排序字段注入风险 |
| 数据库 | 索引、约束 | 唯一键冲突、长度超限、类型不匹配 |

## 四个最常断的地方

### 1. 字段名

- 例子：前端传 `userId`，后端数据库是 `user_id`。
- 坑：前端直接按 `userId` 接收，后端不做自动转换，字段丢失；或者两边各自硬编码转换，一处改全链路崩。
- 方案：统一约定，要么后端返回驼峰，要么前端统一转下划线，或者用序列化工具固定转换规则。

### 2. 类型

- 例子：前端把 ID 当成字符串 `"1001"` 传给后端，后端用 `Long` 接收；空值时前端传 `""`，后端无法转数字，直接抛类型转换异常。
- 坑：ID 字符串和数字混用，空值没有统一标准，时而 `null`、时而空串。
- 方案：ID 统一字符串；空值约定无数据统一返回 `null`，不使用空字符串。

### 3. 分页

- 例子：前端理解 `page=1` 是第一页；后端底层 SQL 的 `offset` 从 0 开始，前端直接把 `page` 当 `offset` 传，第一页的数据被跳过。
- 坑：要不要返回 `total`、是否支持不统计总数（大数据量优化），两边理解不一致。
- 方案：接口契约固定：`page` 从 1 开始，`size` 为每页条数；后端内部计算 `offset = (page - 1) * size`。

### 4. 时间

- 例子：前端传本地时间字符串 `2026-11-16 09:00:00`，不带时区；后端按服务器时区解析，跨时区场景时间偏移 8 小时。
- 坑：有的接口返回毫秒时间戳、有的返回格式化字符串，前端一套代码没法兼容。
- 方案：统一契约，全部使用 UTC 毫秒时间戳，或者统一 ISO8601 带时区格式 `2026-11-16T09:00:00+08:00`。

## 最终做法

1. 先输出接口契约文档，定义入参、出参、字段名、类型、空值规则、分页、时间格式
2. 基于契约建立 mock 服务，前端直接对接 mock，独立完成页面开发，不用等后端
3. 后端开发严格对齐契约，入参校验、序列化转换规则和契约保持一致
4. 联调前，先用 Postman 对接口逐个校验，再接入前端页面

```text
// 一份实际在用的接口约定（字段、类型、示例值、错误码）
// 查询用户列表
GET /api/user/list
入参：
page: number, 页码，从1开始
size: number, 每页条数
userId: string | null, 用户ID，不传/传null代表不筛选
createTimeStart: number | null, 起始时间（毫秒时间戳）
返回：
{
  code: 200,
  data: {
    records: Array<{
      userId: string,
      username: string,
      createTime: number
    }>,
    total: number,
    page: number,
    size: number
  }
}
错误码：400 参数非法，500 服务异常
```

## 怎么验证契约没断

实操顺序：

1. 先用 Postman 单独调用后端接口，核对返回字段、类型、空值、分页、时间
2. 前端对接 mock 跑完所有场景：新增、编辑、删除、筛选、分页
3. 切换到真实后端接口，对比 mock 和真实返回结构，出现不一致立刻回归契约
4. 把契约文档放进仓库，接口变更必须同步修改文档，所有人同步更新

## 坑

- 契约只存在于文档或聊天记录里，接口改了文档没改，前端照着旧字段名开发
- 只对齐成功路径，没定义空值、分页越界、重复提交这些边界
- mock 返回结构和真实接口不一致，前端只对着 mock 测过
- ID、时间在某一层被隐式转换（字符串 → 数字），单测和联调表现不同
